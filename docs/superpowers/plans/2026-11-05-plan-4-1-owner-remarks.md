# План 4.1: правки по первой проверке на планшете

> **Для исполнителя:** соседняя сессия делает по одной задаче и присылает хеш, RED/GREEN, проверки
> мутациями и принятые решения, затем ждёт проверки. Шаги — чекбоксы (`- [ ]`).

**Цель:** исправить шесть замечаний владельца и применить новые правила глобального `AGENTS.md`,
включая зелёный SonarQube по новому коду.

**Архитектура:** логика проходов остаётся чистой функцией в `domain`; новое состояние «ждёт ночи» —
служебная секция `RESTING` без изменения схемы базы. Счётчик полных обновлений живёт в `app`. В `ink`
убирается режим инструмента, ластик остаётся кнопкой стилуса. `sonar-check` учится Gradle в библиотеке
правил, а не в этом репозитории.

**Стек:** Kotlin 2.4.21, AGP 9.5, Compose, Room 3, Robolectric; SonarQube Community Build, JaCoCo.

**Спек:** [замечания владельца](../specs/2026-11-05-first-build-results.md), раздел «Замечания
владельца»; [ТЗ](../../../ТЗ%20приложение-карточки%20с%20эпохами%20повторения%20(Onyx%20Boox%20Go%2010.3).md);
глобальный `~/.claude/AGENTS.md`, скилл `sonar-check`.

## Global Constraints

- Заголовок коммита: `fix: #comment <описание>`. Коммиты прямо в `main`, в этом репозитории без пуша.
- Правила `AGENTS.md` действуют на новый и изменяемый код. Старый код ради них не переписывается, история
  коммитов, прежние планы и спеки не трогаются.
- Из «Стиля кода Java» к Kotlin применяются: глубина вложенных вызовов не больше 4, в среднем до 2;
  правила выделения методов; предикат `filter` без побочных эффектов; перечисление одного типа — внутри
  этого типа. Импорты остаются по стилю Kotlin, правила Commons Lang и Guava здесь неприменимы.
- Имена методов: глагол, булевы `is`/`has`/`can`, `get` только у геттера, `to`/`from`/`of` у преобразований.
- ТЗ правится текстом из задачи, в том же коммите, что и код.
- Схема базы остаётся версии 1. Серийного номера планшета в документах нет.
- Команда проверки задачи: `./gradlew build` (тесты и `verifyModuleGraph`), тяжёлые прогоны по памяти
  пачками, как раньше.
- SonarQube только отдельным проходом, без параллельных сборок и тестов; контейнеры поднимаются перед
  запуском и останавливаются сразу после него при любом результате (`AGENTS.md`, «Этот компьютер»).

## Review Focus

1. В эпохе 1 только ждущие карточки, пул пуст: приложение не падает, показывается «На сегодня всё», счётчики
   проходов не растут при повторном открытии (задача 1).
2. Колоды с планшета, где в эпохе 1 лежат карточки «5/4» из прошлой сборки: открываются без миграции, карточка
   уходит в ожидание или выпускается по новому правилу (задача 1).
3. Возврат в новые единственной карточки эпохи 1: она остаётся в пуле, пока не открыта активная эпоха (задача 2).
4. Вставной проход исчерпан возвратом в новые, а прерванный проход уже тоже пуст (задача 2).
5. Полное обновление отменено на полпути: оно остаётся должным, перо не остаётся выключенным (задача 4).

Порядок в движке:

1. `returnToNew`.
2. Если проход был открыт и исчерпан: обычный проход — `completePass` без цепочки старта; вставной —

меняется. `DeckViewModel` менять не нужно: он публикует новое состояние, а окно подтверждения закрывает исход без
окна; тест это закрепляет.

- База: только компиляция, без тестов. Изменения: `clean` и тесты с отчётами. Аргументы после `--` идут в Gradle. `--no-daemon`: памяти мало.
- В worktree копируется `local.properties`: он не в git, а нужен для SDK.
- Контракт прежний: последняя строка `SONAR: …`, те же коды выхода; вывод упавшей сборки разбирается для Gradle (`FAILURE:`, `e: file://`,
