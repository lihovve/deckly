# Установка Deckly на планшет

Для Onyx Boox Go 10.3 Gen II (Android 15). Сборка только под `arm64-v8a`: нативный считыватель пера
Onyx SDK поставляется лишь для этой архитектуры, на другом планшете приложение не запустится.

## Что нужно

- Компьютер с adb из Android SDK: `~/Android/Sdk/platform-tools/adb` (или путь в переменной `ADB`).
  Системный `/usr/bin/adb` не используйте: по правилам проекта с планшетом работает только adb из SDK.
- Планшет по USB, отладка по USB включена, ключ компьютера подтверждён на планшете (`adb devices`
  показывает `device`, а не `unauthorized`), экран не заблокирован.
- Gradle wrapper из репозитория; отдельно ставить Gradle не нужно.

## 1. Сборка

```
./gradlew :app:assembleDebug
```

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`.

## 2. Установка

```
tools/install-apk.sh app/build/outputs/apk/debug/app-debug.apk app.deckly
```

Обычному `adb install` верить нельзя: связь с планшетом рвётся, большой файл доходит нужного размера, но с
нулями внутри и без ошибки. Скрипт режет APK на куски по 1 МБ, сверяет каждый по md5, склеивает их на
планшете, сверяет целый файл и только потом делает `pm install -r -t`. Обрывы связи он переживает сам,
повторяя шаги.

Второй аргумент (имя пакета) нужен из-за прошивки. После установки BOOX отключает пакет (в
`dumpsys package` появляется `enabled=3`, и `am start` отвечает `Activity class … does not exist`) и сбрасывает
доступ ко всем файлам. С именем пакета скрипт сам включает пакет (`pm enable --user 0`), выдаёт доступ
(`appops set --uid app.deckly MANAGE_EXTERNAL_STORAGE allow`) и проверяет оба.

Коды выхода:

| Код | Что случилось | Что делать |
|---|---|---|
| 0 | Установлено, пакет включён, доступ выдан | — |
| 1 | Неверные аргументы, нет APK или нет adb | Проверьте путь к APK и переменную `ADB` |
| 2 | Планшет не найден или не отвечает | Кабель, отладка по USB, подтверждение ключа, экран разблокирован |
| 3 | Кусок APK не дошёл | Повторить; если не помогает, другой кабель или порт |
| 4 | md5 склеенного APK на планшете не совпал | То же |
| 5 | `pm install` отказал | Текст отказа выведен. Например, при установленной сборке с другой подписью сначала `adb uninstall app.deckly` |
| 6 | Пакет не включился или доступ не выдан | APK уже установлен; выполните шаги 3 и 4 вручную |

Предыдущий прототип (`app.deckly.spike`) удалять не нужно: у него своя папка `Deckly/spike/`.

## 3. Доступ ко всем файлам

База и штрихи лежат в открытой папке `/sdcard/Deckly/` (`deckly.db`, `strokes/`), поэтому приложению нужен
доступ ко всем файлам. Скрипт выдаёт его сам; проверка:

```
adb shell appops get --uid app.deckly MANAGE_EXTERNAL_STORAGE
```

Ответ должен содержать `MANAGE_EXTERNAL_STORAGE: allow`.

Если доступа нет, приложение при запуске показывает окно «Нужен доступ к файлам» с кнопкой «Открыть
настройки». Включите там доступ ко всем файлам для Deckly и вернитесь в приложение: запуск продолжится сам,
перезапускать ничего не нужно.

## 4. Режим обновления экрана BOOX

Режим обновления, выбранный в системных настройках BOOX, главнее режима, который запрашивает приложение.
Поэтому после установки нужно один раз выставить его для Deckly: в настройках BOOX откройте оптимизацию
приложений, найдите Deckly и задайте режим обновления. Какой режим подходит (в прототипе «GC» стирает всё
сразу, но заметно мигает, «REGAL+» не мигает, но стирает остатки не сразу), решает проверка на планшете;
выбранный режим и точные названия пунктов прошивки 4.2 будут записаны здесь по её итогам.

## 5. Запуск

Значок Deckly в списке приложений. Из командной строки:

```
adb shell am start -n app.deckly/.MainActivity
```

Если `am start` отвечает `does not exist`, прошивка снова отключила пакет:

```
adb shell pm enable --user 0 app.deckly
```

Приложение работает только в портретной ориентации, системные панели скрыты; свайп от края экрана их
показывает.

## 6. Удаление и данные

```
adb uninstall app.deckly
```

Колоды и штрихи лежат в `/sdcard/Deckly/` (`deckly.db`, `deckly.db-journal`, `deckly.db.lck` и `strokes/`) и
при удалении приложения остаются. Копию снимают целой папкой, когда приложение не на экране; на новом планшете
её кладут на то же место и запускают приложение. Доступ ко всем файлам после переустановки выдаётся заново
(скрипт делает это сам): без него Android 11+ не даёт открыть базу, созданную не этой установкой.
