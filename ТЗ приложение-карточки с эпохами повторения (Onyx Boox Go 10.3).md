# ТЗ: приложение-карточки с эпохами повторения (Onyx Boox Go 10.3)

Sep 20, 2026 · @Lihov

## Назначение и устройство

Офлайн-тренажёр рукописных карточек для одного пользователя. Сеть, аккаунты и синхронизация не нужны, всё состояние лежит на устройстве.

Целевое устройство — Onyx Boox Go 10.3 (Gen II), единственное поддерживаемое:

| Параметр | Значение |
| --- | --- |
| ОС | Android 15, прошивка Boox 4.2 |
| Экран | 10.3", E Ink Carta, монохром, 1860 × 2480, 300 ppi |
| Процессор, память | Snapdragon 750G, 4 ГБ ОЗУ, 64 ГБ |
| Ввод | ёмкостное касание + активное перо InkSense Plus, боковая кнопка пера работает ластиком |
| Ускоренное обновление экрана (BSR) | нет |

Источник характеристик: [обзор Go 10.3 Gen 2 на eWritable](https://ewritable.net/brands/boox/tablets/boox-go-10-3-gen-2/).

Это читалка с экраном E Ink, а не обычный планшет: экран монохромный, перерисовывается медленно и оставляет следы прежнего изображения. Из этого следуют жёсткие правила интерфейса — они важнее любых привычек обычной Android-разработки:

- Никаких анимаций, плавных переходов, теней и градиентов. Смена экрана — мгновенная перерисовка.
- Только чёрный, белый и две-три градации серого. Ни один смысл не кодируется цветом: состояние показывается формой, рамкой или заливкой.
- Крупные элементы: элемент управления не меньше 64 dp, шрифт от 18 sp, разметка статичная, без перекомпоновки при обновлении данных.
- Ничего не меняется на экране само по себе: ни часов, ни таймеров, ни мигающих индикаторов. Экран перерисовывается только в ответ на действие пользователя.
- Никакой инерционной прокрутки: длинное содержимое листается страницами, а не плавным скроллом.
- Частичное обновление для мелких элементов, полное — при смене карточки и при переходе между экранами. Устройство заметно склонно к гостингу, поэтому полное обновление приложение вызывает само, а не надеется на систему.
- Активное перо засыпает при паузе: первый штрих или касание после простоя может потеряться. Все элементы управления должны срабатывать и от пальца, и от пера.
- Ориентация только портретная, автоповорот выключен.

ТЗ задаёт только эти общие правила. Конкретный вид экранов — расположение элементов, размеры, шрифты, тексты — задан актуальными макетами в папке `design/`: [галерея](design/index.html), [описание дизайна](design/README.md), [холст](design/canvas.json).

## Модель данных

Состояние обучения — положение карточки, её счётчик успехов, счётчики проходов колоды и несколько номеров дней. Расписание считается в проходах, а номер дня задаёт только нижнюю границу интервала. Часов и минут в модели нет.

**Номер дня** — порядковый номер календарной даты на устройстве. Новый день начинается в 4:00, чтобы занятие после полуночи относилось к предыдущему дню. Номер дня нигде не показывается, сроков и просроченных карточек нет: перерыв в занятиях ничего не копит. Если дата на устройстве ушла назад, отрицательная разница дней считается нулём.

**Колода** — независимая единица. У каждой колоды свой пул новых, свои четыре эпохи, свой стек выученных и свои счётчики проходов. Колоды друг на друга не влияют.

| Поле колоды | Смысл |
| --- | --- |
| `id`, `name` | идентификатор и имя, видимое в выборе колоды |
| `activeSection` | секция, открытая сейчас: `NEW`, `EPOCH_1..4`, `LEARNED` |
| `currentEpoch` | какая эпоха активна для обучения, 1–4 |
| `passCount[1..4]` | сколько проходов каждой эпохи уже завершено (нужно для расписания) |
| `cursor` | индекс текущей карточки внутри открытой секции |
| `lastPassDay[2..4]` | номер дня, когда завершился последний непустой проход эпохи; нужен для нижней границы интервала |
| `waitingEpoch` | эпоха 2–4, которую выбрало расписание, но которая ещё не созрела по дням; 0 — никто не ждёт |
| `pausedEpoch`, `pausedCursor` | проход эпохи 2–4, прерванный вставным проходом эпохи 1, и позиция в нём; 0 — прерванного прохода нет |
| `tail[1..4]` | до пяти последних карточек прошлого прохода каждой эпохи в порядке показа; нужно для перемешивания с отступом |

| Поле карточки | Смысл |
| --- | --- |
| `id` | идентификатор |
| `section` | где карточка лежит: `NEW`, `EPOCH_1..4`, `LEARNED` |
| `position` | порядок внутри секции; в эпохе задаётся перемешиванием, в пулах — порядком добавления |
| `successes` | успехи в текущей эпохе, 0 и больше; обнуляется при переезде в другую секцию, кроме спуска после ошибки и неудачной проверки выученных — там значение задаётся явно |
| `sectionDay` | номер дня, когда карточка попала в текущую секцию; в стеке выученных — день попадания туда или последней пройденной проверки |
| `lastSuccessDay` | номер дня последней оценки «знал»; пусто, пока «знал» не было |
| `front`, `back` | две стороны, каждая — список штрихов |
| `createdAt` | только для сортировки пулов, в алгоритме не участвует |
| `postponed` | откладывали ли карточку в текущем проходе; сбрасывается на старте прохода |
| `answerRevealed` | открывали ли ответ этой карточки при обучении в текущем проходе; сбрасывается на старте прохода |
| `failed` | получала ли карточка «не знал» в текущем проходе; сбрасывается на старте прохода |
| `checking` | взята ли карточка из стека выученных на проверку в текущий проход эпохи 4 |

**Сторона карточки** — список штрихов в векторном виде. Штрих: толщина и массив точек `x, y` (при желании плюс нажим). Координаты хранятся в системе координат карточки, а не экрана, чтобы рисунок не зависел от размера области отрисовки. Растр не хранится нигде: ластик должен удалять штрих, а не закрашивать его белым.

Обе стороны создаются независимо и могут быть пустыми — пустая сторона это допустимое состояние, приложение не обязано её запрещать.

## Секции

Карточки колоды лежат в шести секциях, по порядку их движения: пул новых, эпохи 1, 2, 3, 4, стек выученных.

Открыть можно любую из шести секций в любой момент, кроме режима создания и редактирования. Пустая секция открывается тоже: карточки в ней нет, поэтому нет ни действий с карточкой, ни листания.

Активная эпоха обучения и открытая секция — разные вещи: можно открыть эпоху 3, пока обучение идёт по эпохе 1.

## Действия с карточкой

Набор действий зависит от открытой секции. Перевернуть карточку можно в любой секции, с лица на оборот и обратно. Очередная карточка всегда показывается лицом.

| Секция | Действия |
| --- | --- |
| Пул новых | удалить, редактировать, создать новую, листать |
| Активная эпоха | удалить, вернуть в пул новых, оценить «знал» или «не знал», отложить в конец прохода |
| Неактивная эпоха | удалить, вернуть в пул новых, листать |
| Стек выученных | удалить, листать |

Что делают действия:

- Удалить — удаляет карточку после подтверждения. Доступно во всех секциях и в режиме редактирования.
- Вернуть в пул новых — после подтверждения карточка уходит в конец пула, счётчик успехов обнуляется.
- Редактировать — открывает текущую карточку пула в режиме редактирования. В пустом пуле доступно только создание.
- Создать новую — открывает режим создания.
- «Знал» — успех плюс один и показ следующей карточки.
- «Не знал» — в эпохе 1 успех минус один, но не ниже нуля; в эпохах 2–4 карточка помечается и в конце прохода спускается на эпоху ниже (см. «Спуск после ошибки»). Затем показ следующей карточки.
- Отложить в конец — только в активной эпохе, до первого открытия ответа в текущем проходе: переносит карточку в конец прохода. После открытия оборота перенос недоступен, в том числе после возврата к вопросу. Также недоступен, если карточку уже откладывали в этом проходе или она последняя.
- Листать — переход к соседней карточке секции без изменения счётчиков, по кругу: с последней вперёд попадаем на первую.

Оценка «знал» и «не знал» возможна, только когда карточка повёрнута оборотом: ответ должен быть прочитан. Пока видно лицо, оценка недоступна.

Каждая карточка оценивается в проходе ровно один раз. «Не знал» означает «показывай дальше»: в этом проходе карточка больше не покажется. Из эпохи 1 она вернётся в следующем проходе, из эпох 2–4 — в ближайшем проходе эпохи ниже. Показать её ещё раз в этом же проходе можно только переносом в конец, и только один раз.

## Алгоритм обучения

Обучение состоит из проходов. Проход — показ всех карточек одной эпохи ровно по одному разу, от первой до последней в текущем порядке. Пользователь сам эпоху не меняет: её выбирает расписание.

Старт любого прохода — четыре шага строго в этом порядке:

1. Выпуск: карточки эпохи, набравшие порог успехов, уезжают в следующую секцию, их счётчик успехов обнуляется. Из эпохи 1 карточка выпускается, только если её последний «знал» получен позже дня, когда она попала в эпоху 1: между заучиванием и выпуском должна пройти хотя бы одна ночь.
2. Проверка выученных: только для эпохи 4, на каждом втором её проходе — см. «Проверка выученных».
3. Добор: только для эпохи 1 — из пула новых берутся карточки с начала пула, пока в эпохе не станет 40 или пока пул не опустеет.
4. Перемешивание: порядок карточек внутри эпохи случайно меняется, с отступом от прошлого прохода — см. «Перемешивание с отступом».

Выпуск происходит именно на старте следующего прохода, а не в момент оценки «знал». Поэтому карточка, только что переехавшая в эпоху 2, впервые покажется не сразу, а на ближайшем проходе эпохи 2.

Завершение прохода — тоже по шагам, строго в этом порядке:

1. В `tail` эпохи запоминаются до пяти последних показанных карточек прохода.
2. Спуск после ошибки — только в эпохах 2–4 и не для карточек на проверке выученных.
3. Итог проверки выученных — только в эпохе 4.
4. Для эпох 2–4: если проход был непустой, в `lastPassDay` записывается сегодняшний номер дня.
5. Счётчик проходов эпохи растёт на один, расписание выбирает следующую эпоху. Вставной проход эпохи 1 этот шаг пропускает — см. «Длинные проходы — порциями».

### Перенос в конец прохода

Во время прохода активной эпохи карточку можно один раз отложить до первого открытия ответа: она переезжает в конец текущего прохода и покажется после всех остальных. Счётчик успехов при этом не меняется.

- Повторно отложить ту же карточку в этом проходе нельзя. Флаг переноса сбрасывается на старте следующего прохода.
- Последнюю карточку прохода отложить нельзя: она и так в конце.
- Первое открытие оборота при обучении устанавливает `answerRevealed = true`, даже если оборот пустой. После этого перенос запрещён до следующего прохода: обратный переворот, смена секции и перезапуск приложения запрет не снимают. На старте следующего прохода этой эпохи флаг сбрасывается. Создание и возврат карточки в новые устанавливают его в `false`. Просмотр неактивной секции этот флаг не меняет.
- Перенос меняет только порядок текущего прохода. Число карточек и сам проход остаются прежними, после переноса показывается карточка, стоявшая следующей.
- В проходе, который идёт порциями, отложенная карточка уходит в конец всего прохода, то есть в последнюю порцию.

### Пороги и наполнение

| Эпоха | Успехов для перехода | Куда уходит карточка | Нижняя граница интервала | Добор из пула новых |
| --- | --- | --- | --- | --- |
| 1 | 4, последний — не в день попадания в эпоху | эпоха 2 | нет | да, до 40 |
| 2 | 4 | эпоха 3 | 1 день | нет |
| 3 | 4 | эпоха 4 | 3 дня | нет |
| 4 | 3 | стек выученных | 7 дней | нет |

Из пула новых пополняется только эпоха 1. В остальные эпохи карточки поднимаются из предыдущей, опускаются из следующей после ошибки, а в эпоху 4 ещё приходят на проверку из стека выученных. Спуск в эпоху 1 может поднять её выше 40 карточек. Это нормально: добор просто не срабатывает, пока карточек не станет меньше 40.

Порог первой эпохи невысок намеренно. Несколько правильных ответов подряд в первые дни почти ничего не добавляют к долгой памяти, если за ними идут разнесённые повторения. А ночь между заучиванием и повтором память заметно укрепляет.

### Расписание эпох

Порядок эпох задаётся счётчиками завершённых проходов. Счётчики циклические и никогда не сбрасываются:

```text
завершён проход эпохи 1: pass1++;  если pass1 % 5 == 0 -> эпоха 2, иначе -> эпоха 1
завершён проход эпохи 2: pass2++;  если pass2 % 3 == 0 -> эпоха 3, иначе -> эпоха 1
завершён проход эпохи 3: pass3++;  если pass3 % 2 == 0 -> эпоха 4, иначе -> эпоха 1
завершён проход эпохи 4: pass4++;  -> эпоха 1
```

Это даёт последовательность из описания: пять проходов первой эпохи, затем второй; каждый третий проход второй запускает третью; каждый второй проход третьей запускает четвёртую.

### Нижняя граница интервала

Эпохи 2, 3 и 4 начинают проход, только если они созрели. Эпоха созрела, если она пуста или если с конца её прошлого непустого прохода прошло не меньше 1, 3 или 7 дней соответственно. У эпохи 1 границы нет. Пустая эпоха не ждёт: её проход пустой и выполняется сразу, как и раньше. Эпоха 4 на проходе с проверкой выученных считается непустой, если в неё придут карточки на проверку.

Если расписание выбрало несозревшую эпоху, она становится ожидающей (`waitingEpoch`), а ход получает эпоха 1. Пока эпоха ждёт, после каждого прохода эпохи 1 решается только одно: созрела ли ожидающая. Созрела — она получает ход, нет — снова идёт эпоха 1. Счётчик `pass1` при этом растёт как обычно, но правило `pass1 % 5` не действует. Когда проход ожидавшей эпохи завершён, расписание продолжается по обычным правилам.

Если эпоха ждёт, а эпоха 1 и пул новых пусты, проход не начинается: показывается окно «На сегодня всё», после него открывается пул новых. Там можно нарисовать новые карточки, и тогда эпоха 1 снова получит ход. В этом состоянии активной эпохой считается ожидающая. Когда пользователь открывает её, старт прохода выполняется заново, с той же проверкой.

Зачем это нужно: интервал в проходах зависит от темпа. Пока другие эпохи пусты или малы, проходы идут один за другим, и без границы маленькую колоду можно «выучить» за один вечер. Это зубрёжка, после которой память держится плохо. Граница действует только снизу: в обычном темпе она почти не срабатывает, а после перерыва ничего не копится.

### Длинные проходы — порциями

Проход эпохи 2–4, в котором больше 40 карточек, идёт порциями по 40. После каждых 40 оценённых карточек, если в проходе ещё остались карточки, вставляется проход эпохи 1. Вставной проход — обычный проход эпохи 1, со стартом и завершением, но он не меняет `pass1` и не обращается к расписанию: после него прерванный проход продолжается со следующей карточки. Если эпоха 1 и пул новых пусты, вставки нет, и следующая порция идёт сразу.

Прерванный проход нижнюю границу заново не проверяет: он уже начат. `lastPassDay` записывается, когда завершена последняя порция, а счётчик проходов эпохи растёт один раз на весь проход.

Во время вставного прохода активной эпохой считается эпоха 1. Прерванная эпоха на это время — неактивная секция: её можно открыть и просматривать как любую неактивную эпоху — листать, переворачивать карточки, удалять их и возвращать в пул новых, но не оценивать. Просмотр не сдвигает позицию прерванного прохода. Удалённая или возвращённая в новые карточка выпадает из прохода, а порядок и позиция остальных сохраняются.

Зачем это нужно: проход эпохи 3 или 4 может насчитывать сотни карточек и длиться несколько дней. Без вставок он останавливает эпоху 1, а её свежие карточки забываются быстрее всех.

### Перемешивание с отступом

При перемешивании первые m мест нового прохода не занимают карточки, стоявшие на последних m местах прошлого прохода этой эпохи (они записаны в `tail`). Здесь m = ⌈N/4⌉, но не больше 5, где N — число карточек в новом проходе; при одной карточке правило не действует. Правило выполнимо всегда, потому что m не больше половины прохода.

Зачем это нужно: иначе карточка, показанная последней, может сразу же повториться первой. Ответ в этот момент ещё держится в кратковременной памяти, и такой повтор ничего не даёт.

### Спуск после ошибки

Карточка эпохи 2, 3 или 4, получившая в проходе «не знал», в конце прохода переезжает в эпоху ниже. Ей ставится на один успех меньше порога новой эпохи: из эпохи 2 она уходит в эпоху 1 с тремя успехами, из эпохи 3 — в эпоху 2 с тремя, из эпохи 4 — в эпоху 3 с тремя. Одного успеха на более коротком интервале хватит, чтобы на ближайшем старте прохода она поднялась обратно. Новая ошибка опускает её ещё на ступень.

Для карточки, спустившейся в эпоху 1, действует то же правило ночи: днём попадания в эпоху считается день спуска. В самой эпохе 1 спуска нет: «не знал» вычитает один успех, но не ниже нуля. Карточки на проверке выученных не спускаются: для них действует итог проверки.

Спуск идёт в конце прохода, а не на старте следующего, как выпуск. Иначе карточка ждала бы полный длинный интервал своей эпохи, а смысл спуска в том, чтобы проверить её раньше.

Зачем это нужно: ошибка на длинном интервале означает, что интервал оказался для карточки слишком длинным. Если оставить её на месте, она придёт через тот же срок и скорее всего снова забудется. Полный сброс тоже не нужен: забытое переучивается быстрее, чем учится заново.

### Проверка выученных

На старте каждого второго прохода эпохи 4 (когда `pass4` нечётный, то есть на втором, четвёртом и следующих проходах) в эпоху на проверку переезжают до 10 карточек из начала стека выученных — те, что пролежали в стеке не меньше 30 дней. Стек упорядочен по дню попадания в него, поэтому в начале лежат карточки, которые дольше всех не показывались. Взятые карточки помечаются `checking` и в проходе показываются и оцениваются наравне с остальными.

В конце прохода:

- «знал» — карточка возвращается в конец стека выученных, её `sectionDay` обновляется;
- «не знал» — карточка остаётся в эпохе 4 с двумя успехами, то есть на один меньше порога, и дальше идёт как обычная карточка эпохи 4.

Пока карточка на проверке, она лежит в эпохе 4, и с ней доступны те же действия, что с любой карточкой этой эпохи.

Зачем это нужно: после трёх успехов в эпохе 4 забывание не останавливается, а редкие проверки держат память годами. Чем больше стек, тем реже проверяется каждая карточка, так что промежутки между её проверками растут сами.

### Пустые эпохи

Пустая эпоха считается пройденной: её счётчик увеличивается, расписание идёт дальше как обычно. Показывать при этом нечего, поэтому пустой проход выполняется мгновенно и без экрана перехода.

Пустые проходы могут выстроиться в цепочку: пустая эпоха отдаёт ход следующей по расписанию, пока очередь не дойдёт до эпохи с карточками.

Перед стартом каждого прохода приложение считает карточки в пуле новых и во всех четырёх эпохах, а из стека выученных — только готовые к проверке, то есть пролежавшие в стеке не меньше 30 дней. Если сумма равна нулю, проход не начинается: показывается окно «нужно создать карточку», после него открывается пул новых. Когда пользователь потом открывает активную эпоху, старт прохода выполняется заново, с той же проверкой.

При ненулевой сумме цепочка пустых проходов конечна. Пул новых доливается в эпоху 1 на её старте. До эпохи 4 расписание доходит не больше чем за 30 проходов эпохи 1, до прохода эпохи 4 с проверкой выученных — не больше чем за 78 проходов, то есть за два полных круга расписания. Цепочка может остановиться и раньше — на окне «На сегодня всё», если непустая эпоха ещё не созрела. Цикл в коде всё равно стоит ограничить сотней итераций с явной ошибкой — это страховка от бага, а не часть логики.

### Откуда эти правила

Правила опираются на исследования памяти:

- польза распределённого повторения по сравнению с зубрёжкой: Cepeda и др., 2006 и 2008; Kornell, 2009 — на флеш-карточках;
- роль сна между заучиванием и повтором: Mazza и др., 2016;
- малая польза лишних успехов при первом заучивании, если за ним идут разнесённые повторения: Rawson и Dunlosky, 2011; Rohrer и др., 2005;
- полезно только трудное, но удавшееся припоминание, а после ошибки нужна скорая повторная проверка: Bjork, 1994; Pashler и др., 2005;
- долговременное сохранение через редкие повторы: Bahrick и др., 1993.

## Создание и редактирование

В этом режиме карточку рисуют пером и стирают, как лист блокнота.

Инструменты и ничего сверх того: перо, ластик, выбор толщины, отмена последнего действия. Ни цвета, ни фигур, ни лассо, ни ввода текста с клавиатуры, ни изменения масштаба.

- Перо рисует штрих, ластик удаляет штрих целиком при касании, а не закрашивает белым.
- Отмена снимает последнее действие, включая стирание. Глубина не меньше 20 шагов.
- Боковая кнопка стилуса работает ластиком, пока нажата.

Стороны рисуются по отдельности, переключаться между лицом и оборотом можно в любой момент. Незаконченный рисунок при переключении стороны не теряется.

Из режима выходят сохранением или удалением. Удаление работает как отмена создания: при создании новой карточки оно выбрасывает черновик, при редактировании существующей — удаляет карточку. Оба случая спрашивают подтверждение.

Куда попадает карточка после сохранения:

- новая карточка — в конец пула новых, успехи ноль;
- отредактированная — остаётся там же, где была, счётчик успехов не трогается.

После сохранения приложение возвращается в ту секцию, из которой вошли в редактирование.

## Переход между эпохами и просмотр

Когда проход закончен и расписание выбрало следующую эпоху, показывается экран перехода. Старт нового прохода — выпуск, проверка выученных, добор, перемешивание — выполняется до его показа. Проход начинается с первой карточки, когда пользователь закроет экран перехода.

Вставной проход эпохи 1 и возврат к прерванному проходу тоже начинаются с экрана перехода: на нём видно, какая эпоха идёт и сколько карточек в ней осталось.

Экран перехода появляется только перед эпохой, в которой есть карточки. Пустые проходы проскакивают молча, иначе пользователь получил бы три экрана подряд.

Просмотр неактивной секции — это чтение без обучения. Листание, переворот карточки, удаление и возврат в пул новых работают; оценки нет, счётчик успехов и счётчики проходов не меняются. Вручную вернуть карточку из стека выученных в обучение нельзя — только посмотреть или удалить. В эпоху 4 она попадает только через проверку выученных.

При возврате к активной эпохе позиция в проходе сохраняется: приложение продолжит с той карточки, на которой ушли смотреть другую секцию.

## Колоды и хранение

В управлении колодами можно создать колоду, переименовать, удалить и выбрать текущую, а также экспортировать и импортировать. Открыта всегда ровно одна колода: приложение запускается на той колоде и той секции, где его закрыли.

Рабочее хранилище — локальная база, запись после каждого изменения. Незаписанного состояния в памяти оставаться не должно: устройство засыпает само, и потерять проход из-за этого нельзя. Минимум, что сохраняется сразу: оценка карточки, переход между эпохами, спуск и итог проверки в конце прохода, начало и конец вставного прохода, ожидание эпохи, сохранение и удаление карточки, первое открытие ответа (`answerRevealed`).

Экспорт и импорт идут через файловую систему, без облака. Один файл — одна колода: карточки со штрихами, секции, счётчики успехов, счётчики проходов, номера дней, ожидающая и прерванная эпохи, то есть состояние восстанавливается полностью. Формат — JSON, при желании упакованный в zip.

Импорт всегда создаёт новую колоду и не трогает существующие: слияние и разрешение конфликтов не нужны. Выбор файла — системный, через Storage Access Framework.

Если файл повреждён или это не файл колоды, импорт отменяется с понятным сообщением, а не создаёт полупустую колоду.

## Техническая часть

Нативное Android-приложение, минимальная версия API 30, целевая — Android 15. Kotlin. Разметка на View или Compose, но без анимаций и без библиотек, которые их навязывают. Никаких сетевых разрешений.

Рисование — самое рискованное место, и решать его надо в первую очередь, до всей остальной логики:

- Основной путь — сырое перо Onyx SDK: штрих рисует прошивка напрямую через контроллер экрана, задержка почти нулевая. Детали ниже.
- Запасной путь, который тоже обязан работать: обычный `Canvas`, события пера по `MotionEvent`, последний штрих — частичным обновлением экрана. Включается, если SDK не инициализировался.
- Первая задача разработки — прототип рисования на самом устройстве, до остальной логики. Эмулятор не воспроизводит ни задержку пера, ни поведение экрана.

### Onyx SDK

Официальный SDK у BOOX есть, но документация к нему устарела. Актуальные версии и подводные камни видны по живому open-source приложению Notable, которое обновило SDK 26 сентября 2026.

| Библиотека | Версия | Зачем |
| --- | --- | --- |
| onyxsdk-pen | 1.5.8 | TouchHelper: сырое перо, ластик кнопкой пера |
| onyxsdk-device | 1.3.6 | EpdController: режимы обновления экрана |
| onyxsdk-base | 1.8.9 | общая база для двух других |

Репозиторий BOOX работает только по HTTP, поэтому в Gradle нужен `allowInsecureProtocol = true` для `http://repo.boox.com/repository/maven-public/`, плюс `https://jitpack.io`.

Правила, без которых SDK не заработает или будет сбоить:

- В `Application.onCreate` вызвать `ResManager.init(this)`. Без этого pen 1.5.8 падает с `ExceptionInInitializerError` на первом же штрихе.
- Собирать только под `arm64-v8a`: с версии pen 1.5.5 нативный считыватель пера поставляется лишь для этой архитектуры.
- Пока сырое перо включено, прошивка замораживает обновление экрана. Область рисования задаётся через `setLimitRect`, элементы управления режима редактирования идут в список исключений. На время диалогов, переворота стороны и паузы activity перо выключается.

* Открытие сессии сырого пера стоит около 60 мс: не пересоздавать её на каждый штрих и настраивать только когда поверхность уже готова.
* Стиль пера и ластика задавать до включения рисования. Колбэки приходят через `post()`, когда прошивка уже зафиксировала стиль штриха.
* Ластик кнопкой пера приходит отдельными колбэками `onBeginRawErasing` и следующими; по их точкам ищутся пересечённые штрихи и удаляются целиком.
* Только базовый стиль пера: часть кистей Neo из SDK нестабильна и роняет приложение.

Режим обновления экрана, выбранный в системных настройках BOOX, главнее режима, который запрашивает приложение. Поэтому в инструкцию по установке входит шаг: выставить приложению режим обновления в оптимизации приложений BOOX.

Главный риск: ни один найденный проект не проверен на Go 10.3 Gen II. Notable проверяли на Note Air 4C, а у Gen II активное перо InkSense Plus вместо EMR и Android 15. Как TouchHelper работает с этим пером, выясняется первым прототипом; не заработает — включается запасной путь на обычном Canvas.

Источники: [документация Pen SDK от BOOX](https://raw.githubusercontent.com/onyx-intl/OnyxAndroidDemo/master/doc/Onyx-Pen-SDK.md), [обновление SDK в Notable](https://github.com/Ethran/notable/pull/332), [подключение репозитория в Notable](https://github.com/Ethran/notable/blob/main/settings.gradle), [руководство BOOX о режимах обновления](<https://onyxboox.com/files/manuals/BOOX_Poke4series_User_Manual_(20220617).pdf>). Код [Notable](https://github.com/Ethran/notable) стоит дать агенту как образец жизненного цикла пера.

Отсечение ладони: рисуют только события с `TOOL_TYPE_STYLUS` и `TOOL_TYPE_ERASER`, касания пальцем в области рисования игнорируются. Касание ладонью по карточке вне редактирования тоже ничего не делает, в том числе не переворачивает её. Элементы управления срабатывают и от пальца, и от пера.

Обновление экрана: частичное при рисовании штриха и при смене мелких элементов, полное при смене карточки и экрана. Устройство склонно к гостингу, поэтому полное обновление вызывается приложением явно, а не по усмотрению системы.

Активное перо засыпает и первый штрих или касание после паузы может потеряться — это особенность железа, в приложении на одиночный штрих ничего важного не вешается.

Производительность: карточка со штрихами открывается меньше чем за 200 мс, штрихи хранятся и рисуются без сглаживающих пересчётов всего холста при каждом касании.

## Принятые решения и отложенное

Решения, дописанные при составлении ТЗ и подтверждённые.

- Оценка «знал» и «не знал» требует перевёрнутой карточки. Прямо оговорено было только про «знал», но и «не знал» имеет смысл отмечать после ответа.
- Листание зациклено.
- В неактивной эпохе карточку можно удалить или вернуть в пул, не дожидаясь её эпохи.
- Пустые проходы не показывают экран перехода.
- Импорт всегда создаёт новую колоду.
- Интервалы считаются в проходах, но у эпох 2–4 есть нижняя граница в днях: 1, 3 и 7. День начинается в 4:00. Сроков и просрочки нет.
- Пороги успехов — 4, 4, 4 и 3; из эпохи 1 карточка выходит только после ночи.
- Ошибка в эпохах 2–4 опускает карточку на ступень, и до порога ей там не хватает одного успеха.
- Проход эпохи 2–4 длиннее 40 карточек идёт порциями со вставными проходами эпохи 1.
- Перемешивание не ставит в начало прохода карточки, показанные последними в прошлом.
- Стек выученных выборочно проверяется через эпоху 4; вручную вернуть из него карточку в обучение по-прежнему нельзя.

Сознательно не делаем в первой версии: подсказки и статистику, звук, подсветку, поворот экрана, любую синхронизацию, распознавание рукописного текста, изменение размера карточки, запись ответа пером перед переворотом.

## Приёмочные проверки

Эти сценарии должны проходить на автотестах логики, без устройства.

1. Последовательность эпох при непустых эпохах, если нижние границы не срабатывают (между проходами прошло достаточно дней), совпадает с эталоном: 1 1 1 1 1 2 1 1 1 1 1 2 1 1 1 1 1 2 3 1 1 1 1 1 2 1 1 1 1 1 2 1 1 1 1 1 2 3 4.
2. Карточка первой эпохи с четырьмя успехами, последний из которых получен позже дня её попадания в эпоху, уезжает во вторую на старте следующего прохода первой эпохи, а не раньше. Если все успехи получены в день попадания, карточка остаётся в первой эпохе, сколько бы «знал» ни набрала, пока не получит «знал» в другой день.
3. Карточка, приехавшая во вторую эпоху, не показывается до ближайшего прохода второй эпохи.
4. Первая эпоха добирается из пула ровно до 40; при пуле в 10 карточек в эпохе оказывается 10, и это не ошибка.
5. Оценка «не знал» на карточке первой эпохи с нулём успехов оставляет ноль.
6. Пустая вторая эпоха увеличивает свой счётчик и отдаёт ход дальше, экран перехода не показывается.
7. Колода, где пусты пул новых и все эпохи, на старте прохода показывает окно «нужно создать карточку» и открывает пул новых. То же, если карточки есть только в стеке выученных и ни одна не пролежала там 30 дней. Если карточки есть только в эпохе 4 и она созрела, расписание доходит до неё не больше чем за 30 пустых проходов эпохи 1; если не созрела — показывается окно «На сегодня всё».
8. Возврат карточки из эпохи в пул новых ставит её в конец пула с нулём успехов.
9. Экспорт и импорт колоды дают то же состояние: те же секции, порядок, успехи, счётчики проходов, номера дней, ожидающая и прерванная эпохи.
10. Убийство приложения сразу после оценки «знал» не теряет успех.
11. Отложенная карточка уходит в конец прохода, показывается после всех остальных, её успехи не меняются; повторно отложить её в этом проходе нельзя, а после убийства приложения порядок прохода сохраняется.
12. До открытия ответа перенос доступен для неотложенной и непоследней карточки. Первое открытие ответа, включая пустой оборот, блокирует перенос. Возврат к вопросу, смена секции и перезапуск приложения не снимают блокировку. На старте следующего прохода этой эпохи флаг открытия ответа сбрасывается; остальные ограничения переноса продолжают действовать.
13. Проход эпохи 2 завершён в день D. До дня D+1 эпоха 2 не начинается: расписание её выбирает, она ждёт, а ход получает эпоха 1; при пустых эпохе 1 и пуле новых показывается окно «На сегодня всё». В день D+1 эпоха 2 получает ход на ближайшем переходе. То же для эпох 3 и 4 с границами 3 и 7 дней. Оценка в 3:59 относится к предыдущему дню, в 4:00 — к новому. Пустая эпоха не ждёт, даже если её прошлый непустой проход был сегодня.
14. Темп не ускоряет путь. При любом числе оценок в день и одних «знал» ни одна карточка не покидает первую эпоху в день попадания в неё, а в стек выученных карточка попадает не раньше чем через 38 дней после попадания в первую эпоху.
15. Карточка третьей эпохи с «не знал» в конце прохода оказывается во второй эпохе с тремя успехами. После одного «знал» в проходе второй эпохи она уезжает в третью на старте следующего прохода второй эпохи. Карточка второй эпохи с «не знал» уходит в первую с тремя успехами: «знал» в день спуска её не выпускает, «знал» на следующий день выпускает на ближайшем старте прохода первой эпохи. Спуск в первую эпоху, где уже 40 карточек, даёт 41, и добор не срабатывает.
16. Проход эпохи 4 из 100 карточек при непустой эпохе 1 идёт так: 40 карточек эпохи 4, проход эпохи 1, ещё 40, проход эпохи 1, последние 20. `pass1` при этом не меняется, `pass4` растёт на один, `lastPassDay[4]` записывается после последней порции. Отложенная карточка показывается в последней порции. Убийство приложения во вставном проходе не теряет ни его позицию, ни позицию прерванного.
17. В проходе из N ≥ 2 карточек ни одна из последних m = min(5, ⌈N/4⌉) карточек прошлого прохода этой эпохи не оказывается среди первых m. При двух карточках последняя показанная никогда не идёт первой.
18. Если карточки есть только в стеке выученных и часть из них готова к проверке, расписание доходит до прохода с проверкой не больше чем за 78 пустых проходов.
19. Если дату на устройстве перевести назад, ни одна нижняя граница не нарушается: эпохи 2–4 ждут, пока дата снова не уйдёт вперёд, и приложение не падает.
