# Вариант C / v3 — «Спокойный лист»

Новая версия дизайна от 02.11.2026. Предложение для обсуждения, не реализация приложения. Основано на ТЗ в корне проекта и всех макетах B. Исходный вариант B сохранён.

Открыть `index.html` в браузере — галерея из 40 экранов. Открыть `canvas.json` в редакторе макетов — отдельный холст C с теми же экранами. Обычные HTML работают локально, без библиотек, сервера и загрузки шрифтов. Вариант `.dc.html` предназначен для редактора; импорт в сам редактор в этой среде не проверялся.

## Что в B стоит сохранить

Шесть постоянно доступных секций, отдельную отметку активной эпохи, крупные кнопки, монохром, возврат к обучению из просмотра, отсутствие оценки до переворота, короткий набор инструментов рисования. Эти решения соответствуют назначению устройства и ТЗ.

Шрифтовая надпись на карточках — условное обозначение рукописи, не предложение добавить текстовый ввод. В Android на этом месте отображаются векторные штрихи.

## Выбранное направление и альтернативы

Мой выбор — сохранить структуру B и переработать иерархию и расположение действий. Это даёт узнаваемый интерфейс без изменения алгоритма. Цена: отдельная строка переворота занимает часть высоты карточки.

Рассмотрены ещё два направления: небольшая косметическая правка B (дешевле, но сохраняет перемещение оценок и наложение меток) и полноэкранная карточка со скрытой навигацией (больше места рисунку, но секции и статус обучения становятся менее заметны). В C шесть секций доступны непосредственно.

## Правила для реализации

- Открытая секция и активная эпоха независимы. Рамка показывает открытую, надпись «учим» — активную. Нажатие неактивной эпохи не меняет расписание.
- При просмотре доступен явный возврат к текущей карточке обучения. Просмотр и переворот не изменяют счётчики. После листания карточка всегда открывается лицом; листание зациклено.
- «Оценено» — количество уже оценённых карточек прохода. Перенос в конец не увеличивает его. При удалениях и возврате карточек в пул знаменатель должен отражать фактический состав прохода; детали пересчёта требует согласовать в алгоритме, ТЗ их не фиксирует.
- «Не знал» уменьшает успехи до минимума 0, «Знал» увеличивает. Оба действия доступны только на обороте и сразу открывают следующую карточку лицом. Оформление оценок равнозначное, без навязывания положительной оценки.
- «В конец» недоступна для уже отложенной и последней карточки. Положение кнопки сохраняется; причина указана под ней. При одном элементе это последняя карточка.
- Успехи показываются числом; точки вспомогательные. При достижении порога показать, например, «8 / 8 · к переходу». Перемещение выполняется только на старте следующего прохода, не при оценке.
- Набор меню: новые — редактировать, удалить; эпохи — вернуть в новые, удалить; выученные — только удалить. В пустой секции меню карточки и листания отсутствуют; в пустом пуле есть создание.
- Перед экраном перехода выполнены выпуск, добор и перемешивание. Пустые проходы не получают собственного экрана. Если карточек для обучения нет, диалог ведёт в новые.
- Редактор не показывает навигацию по секциям. Стороны независимы, могут быть пустыми. Переключение стороны не теряет штрихи. Выход — сохранить или подтвердить удаление/выбрасывание. Системная кнопка «Назад» должна вызывать тот же выбор, а не скрыто терять правки.
- Перо, ластик целого штриха, три толщины, отмена не менее 20 действий. Боковая кнопка пера временно включает ластик. На холсте игнорируются пальцы и ладонь; элементы управления принимают палец и перо.
- Диалоги блокируют фон, переводят фокус внутрь, после закрытия возвращают его на вызвавший элемент. По умолчанию выделено безопасное действие. Системное «Назад» закрывает подтверждение без удаления. В редакторе перед диалогом отключается сырое перо.
- Список колод постраничный, без инерционной прокрутки. Длинные названия — максимум две строки, затем многоточие, полное имя доступно в меню колоды. Ноль колод: заголовок «Создайте первую колоду», создание и импорт; кнопки возврата к карточкам нет. Это правило описано здесь, отдельного макета первого запуска нет.
- Пустое/пробельное имя колоды: сохранить недоступно, рядом с полем «Введите название». ТЗ не задаёт уникальность имён; дизайн её не вводит. Клавиатура нужна только для имён колод.
- Экспорт и импорт используют системный файловый интерфейс. Отмена выбора возвращает к колодам, успешный импорт добавляет новую колоду. Ошибка не создаёт частичную колоду. Ошибка экспорта: «Не удалось сохранить файл. Выберите другое место» и действия повторить/закрыть.
- Все изменения сохраняются локально по ТЗ. Восстановление после сна или закрытия не сбрасывает позицию, успехи или перенос. Макеты не подменяют требования к базе и восстановлению.

## Размеры и E Ink

Фрейм 992 × 1323 сохранён для сопоставимости с B. Это **условные единицы макета**, не подтверждённая Android density. Нельзя получать dp простым делением физических пикселей на 300 ppi: Android использует логическую плотность и системные отступы. На устройстве нужно проверить доступную область, системные панели и размер шрифта.

Поля 32, промежутки 20, контролы от 80 единиц, нижние оценки 112; шрифты интерфейса 18–40. При переносе на Android минимальная цель касания **64 dp**, текст **18 sp**, независимо от масштабирования макета. Область рисунка имеет одну систему координат на чтении и редактировании; разный размер отображения не обрезает рисунок и не растягивает пропорции.

Чёрный и белый плюс #555 для второстепенного текста и #DDD для дорожки прогресса. Недоступность обозначается также пунктиром и реальным disabled. Нет теней, анимаций, таймеров, сетевых ресурсов. Полное обновление при смене карточки и экрана, частичное для мелких изменений; пригодность выбранной геометрии и заливок по гостингу проверяется на реальном Boox.

## Что можно проверить в макетах

- `front → back → front`: доступность оценок и постоянные координаты.
- `last → transition → epoch2`: завершение и переход к первой карточке следующей эпохи.
- `front → browse → front`: различие просмотра и обучения.
- `pool → editor → discard` и `pool → edit → delete-edit`: разные последствия выхода из редактора.
- `decks → deck-menu → delete-deck`: удаление колоды с подтверждением.
- `empty`, `empty-pool`, `need-card`, `import-error`: отсутствие карточек и ошибка файла.

Навигация демонстрационная: страницы содержат фиксированные данные. Оценки не вычисляются, стрелки не листают реальные карточки, инструменты не рисуют, формы не сохраняются. Некоторые ссылки сходятся к одному примеру; это не обещание рабочего алгоритма. Все макеты вынесены отдельно, чтобы состояния можно было оценивать без прохождения сценария.

Для проверки перед разработкой нужны: реальные размеры целей касания на устройстве, читаемость при выбранном масштабе системы, работа активного пера и скорость/гостинг обновлений. Веб-макет этого не подтверждает.
